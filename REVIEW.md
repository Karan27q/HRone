# REVIEW.md

Defects found in the starter `app/main.py`, in the order I met them. "Line" refers to the starter file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Compares the **floored minutes** to 10 (`minutes > 10`) instead of checking for strictly more than 10:00. Anything from 09:40:01 to 09:40:59 is floored to 10 and returns 0, but R2 says it is late with `late_minutes` = 10. | Shift 09:30, punch-in 09:40:01 -> expected 10, got 0. | Work in seconds: late only if `seconds > 600`, then `seconds // 60`. |
| 2 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(...)`, i.e. on the punch-in's own date and in its own (server-local / naive) time zone, not in IST on the record's attendance date. Overnight shifts break too. | Server in UTC: a 10:01 IST punch-in (04:31 UTC) on a 09:30 shift returns 0 instead of 31. | `ist_at(record_date, shift_start)`: the shift start is built in IST on the R1 attendance date. |
| 3 | `compute_work_hours` | `round()` works on a binary float, so exact halves are not rounded half-up (R4): the float for 4.505 is just below 4.505, so it rounds down. No truncation of seconds either. | 4h 30m 18s = 16218 s = 4.505 h: starter gives 4.5, expected 4.51. Same for 54 s (0.015 h): 0.01 instead of 0.02. About 1 in 70 whole-second durations differs. It does not flip `half_day` (checked: no differing case crosses 4.50), but it changes reported hours and averages. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`; instants truncated to seconds on input. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); the shift end is always on the same date, so overnight shifts are wrong; mixes an aware `end` with a possibly naive `punch_out`, which raises `TypeError`. | Punch-out 18:40 on a 18:30 shift returns 10 (expected 0). Overnight 22:00-06:00 shift, punch-out 06:40 next day, returns 1480 (expected 40). Naive `punch_out` -> `TypeError` (500). | Floor to minutes, keep only if `>= 30`; shift end on `date + 1 day` for overnight shifts; everything timezone-aware. |
| 5 | `punch_in`, timestamp | `datetime.fromtimestamp(ms / 1000)` returns a **naive server-local** datetime, so the stored instant and everything derived from it depends on the server's time zone; `if body.punched_at` treats `0` as "not given"; no sub-second truncation (R1); no range check, so a huge value such as `10**15` raises `ValueError`/`OverflowError` -> 500. | `{"punched_at": 1000000000000000}` -> 500; run the server in UTC vs IST and compare stored times. | `ms_to_dt`: epoch ms -> aware UTC, truncated to whole seconds; `is not None` check; bounds enforced by the model (422). |
| 6 | `punch_in`, date | `date` is the server-local calendar date, not the **IST** date; no overnight rule (R1). | Server in UTC, punch-in 01:00 IST -> stored on the previous day. 05:00 IST for a 22:00–06:00 employee must belong to yesterday. | `attendance_date()` implements R1 incl. overnight. |
| 7 | `punch_in`, employee | `db.employees.find_one` can return `None`; `emp["shift_start"]` -> `TypeError` -> **500** instead of 404. | Unknown `emp_code`. | `get_employee()` raises 404. |
| 8 | `punch_in`, race | Check-then-insert (`find_one` then `insert_one`) with no unique index: two simultaneous requests both pass the check and both insert. | Fire two parallel punch-ins. | Unique index `(emp_code, date)`; `DuplicateKeyError` -> 409. |
| 9 | `PunchInIn` | `punched_at: Optional[int]` in pydantic v2 lax mode **coerces** `"123"` and `12.0`; seconds-looking and out-of-range values pass; `status: str` accepts `ABSENT`, `LEAVE` or `"banana"`. | `{"punched_at": "1783312500000"}` or `{"status": "banana"}` returned 201. | `StrictInt` with 1e11..4.1e12 bounds; `status` is `Literal[PRESENT, WFH, ON_DUTY]`. |
| 10 | `punch_in` response | Returns `punch_in` as a datetime and adds `id` = the MongoDB `_id`. The contract says epoch ms and "`_id` never appears". | Response contains `"id": "66f..."`. | `record_out()` is the only serializer: ms instants, no `_id`, gap defaults. |
| 11 | `create_employee`, race + validation | `find_one` then `insert_one` with no unique index (concurrent creates both succeed); **no validation** at all (emp_code format, e-mail, lengths, shift format, `shift_start == shift_end`, real `joined_on`). | Two parallel creates; `{"shift_start":"25:99"}` -> 201. | Unique index on `emp_code`, `DuplicateKeyError` -> 409, pydantic patterns/lengths and a model validator (422). |
| 12 | `create_employee` response | `created_at = datetime.now()` (naive, local) and returned as a datetime, not epoch ms. | Response `created_at` is an ISO string without zone. | `now_utc()` stored, `dt_to_ms()` returned. |
| 13 | `list_employees` | `skip = page * page_size` (page 1 skips the first page); `total` ignores the `department` filter; no sort (contract: `emp_code` asc); `page=0` -> negative skip -> pymongo error (500); `page_size` unbounded; `_id` projected out but `created_at` returned raw. | `?page=1` returns items 21–40; `?department=X` shows the global total. | `skip=(page-1)*size`, `count_documents(q)`, sort by `emp_code`, `Query(ge=1, le=100)`, index `(department, emp_code)`. |
| 14 | `list_attendance` | Loads **every matching document into memory**, sorts and slices in Python; no index; sort has no `emp_code` tie-breaker; leaks `_id` as `id`; datetimes not ms; `status` and dates unvalidated, `date_from > date_to` accepted; no page bounds; legacy docs (no `history`/`half_day`) pass through as-is. | 100k docs: slow and memory-heavy; `?status=bogus` -> 200. | DB-side `find().sort().skip().limit()`, indexes `(date -1, emp_code 1)`, `(status, date -1, emp_code)`, `(emp_code, date)`; validation (422); `record_out()` fills gaps. |
| 15 | module level | `MongoClient(...)` without `tz_aware=True`: every datetime read back is naive, so comparisons with aware values raise `TypeError`. | `punch_out - punch_in` crashes after the first read. | `tz_aware=True` plus `as_aware()` / `dt_to_ms()` that treat naive as UTC. |
| 16 | `/health` | Always returns 200, even when MongoDB is down. | Stop MongoDB, call `/health`. | Pings MongoDB; 503 on failure. |
| 17 | startup | No indexes are created anywhere (the seeded DB only has `_id`). | `explain` shows COLLSCAN. | `ensure_indexes()` in the lifespan hook (idempotent), retried from `/health` if MongoDB was not up yet. |

**Looked at and judged fine**

- `IST = timezone(timedelta(hours=5, minutes=30))`: correct constant, kept.
- `load_dotenv()` with the default `override=False`: real environment variables already win over `.env`, as required.
- `doc.pop("_id", None)` after `insert_one`: needed because `insert_one` mutates the dict, harmless (but the surrounding response was still wrong, see #10).
- `{"_id": 0}` projection in `list_employees`: fine in itself; replaced only because I serialize through `employee_out()`.
- The helpers are reusable in spirit, but none was reusable as written; I kept the names and rewrote the bodies (they now also take the record date / the employee for overnight shifts).
